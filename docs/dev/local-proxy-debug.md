# 本地代理调试

这一节讲怎么在本地起 gost 代理、连接远程 ws 隧道，通过这个代理来调试代码。

## 背景

抖音会校验登录 Cookie 的出口 IP。本地调试时，如果直接用本机 IP 跑，会和你线上任务的出口 IP 不一致，导致登录态掉。所以调试时要让本地流量走远程隧道，借用一个固定的出口 IP。

链路：

```
本地程序 → 本地 gost（HTTP 代理）→ wss 隧道 → 远程 gost → 目标站
```

## 1. 远程已有一套 gost

Docker 部署（`deploy/docker.md`）或云函数部署（`deploy/fc.md`）都会有一个 gost 隧道服务。你需要它的：

- 隧道地址（`ws://` 或 `wss://`）
- 账号 / 密码

## 2. 本地起 gost 客户端

用 gost 的 `-L`（本地监听）+ `-F`（转发到隧道）参数：

```bash
gost -L http://127.0.0.1:<本地端口> -F "<隧道URL>"
```

例如：

```bash
gost -L http://127.0.0.1:15113 -F "ws://gost:密码@服务器IP:9000?path=/ws"
```

> 隧道地址必须带端口：`ws://` 不会自动补默认端口，缺端口会拨号失败，表现成「none node available」。

## 3. 让程序走这个代理

`.env` 里设：

```
PROXY_ADDRESS=http://127.0.0.1:15113
```

或在启动时指定。程序里的浏览器会通过这个 HTTP 代理出网，出口 IP 就是远程隧道那一端的 IP。

## 4. 验证出口 IP

走代理请求一个 IP 回显服务，确认出口 IP 已经是远程的：

```bash
curl -x http://127.0.0.1:15113 https://cip.cc
```

## 5. 排查手法

如果隧道拨号失败，用下面的方式手动起客户端，能看到 gost 的真实报错：

```bash
gost -L http://127.0.0.1:<port> -F "<隧道URL>"
```

然后用 `curl -x` 走这个代理请求 `https://cip.cc`，观察 gost 输出。

常见坑：

- 隧道地址缺端口 → 报 `none node available`
- 云函数冷启动导致首次握手超时 → 多试几次，或给云函数配最小实例数
- 本地 gost 忘关 → 云函数按活跃时长一直计费，调试完记得关
