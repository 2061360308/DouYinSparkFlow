# 问答

## 配置生成器相关

**问：网页版配置生成器安全吗？**

答：它是托管在 GitHub Pages 上的单页应用，源码在 `docs` 目录开源可审计，数据在本地处理、不上传。但网页版无法自动抓 Cookie，需要手动导出粘贴。

**问：为什么主推 configTool，而不是网页版？**

答：configTool 能自动抓登录态、自动拉会话列表、支持配套代理对齐出口 IP；网页版只能手动粘贴 Cookie，且出口 IP 很难与定时脚本对齐，登录态容易掉。

**问：configTool 填写后需要保存吗？**

答：不需要。所有改动会自动写回 `.env`，左侧预览的就是真实写入内容。

## 登录态相关

**问：为什么明明抓到 Cookie 了，任务还是登录失败 / 登录态掉？**

答：十有八九是**出口 IP 不一致**。抖音校验 Cookie 的出口 IP，抓 Cookie 的出口必须和跑任务的出口一致。见 [Cookie 与出口 IP](guide/02-cookie与出口IP.md)。

**问：登录态多久会失效？**

答：取决于抖音的策略和你的使用频率，没有固定时间。掉登录态后，用 configTool 的「刷新登录信息」重新登录一次即可。

## 部署相关

**问：三种部署方式选哪个？**

答：有服务器选 **Docker（最推荐）**；没有服务器且能少量付费选**云函数**（可用性待验证）；两者都没有才考虑 **GitHub Action**（过时，需私有仓库 + 自备代理）。见 [选择部署方式](guide/01-选择部署方式.md)。

**问：GitHub Action 为什么老被踢 / 登录态掉？**

答：两个原因：GitHub 对公共仓库 Action 审查严格；runner 出口 IP 每次漂移导致登录态掉。需要私有仓库 + 固定代理，很折腾，建议直接换 Docker。

**问：云函数现在能用吗？**

答：**还没经过测试，可用性未知**。适合有动手能力的用户先行验证并反馈。见 [云函数](deploy/fc.md)。

## 使用相关

**问：目标好友匹配不上怎么办？**

答：确认备注 / 昵称 / 抖音号填的是否准确，支持这几种方式智能匹配。如果好友在折叠组或陌生人组，主列表扫不到，会提示「未覆盖折叠组 / 陌生人组」。

**问：怎么排查问题？**

答：先把 `.env` 的 `LOG_LEVEL` 改成 `Debug`，看 `logs/app.log`。日志会详细记录登录判定、会话扫描、发送过程。

**问：多账号怎么配？**

答：configTool 支持添加多个账号，每个账号有独立的浏览器配置目录和登录态，可分别登录、分别设目标好友。
