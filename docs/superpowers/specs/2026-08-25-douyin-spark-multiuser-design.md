# 抖音续火多用户管理系统设计规格

**日期：** 2026-08-25
**状态：** 待用户书面确认
**部署目标：** `39.106.220.31` 上的独立 Docker Compose 项目
**现有业务保护对象：** 现有 BPS Web、Celery、Nginx、Redis、MySQL 五个容器，以及 `/opt/douyin-spark-flow` 的既有续火脚本与回滚配置

## 1. 目标

构建一个面向少量受邀用户的续火管理系统。普通用户登录后，只能添加自己的抖音账号、配置发送对象、每日发送时间和消息内容，并查看自己的执行结果。管理员可以创建用户、查看全部任务和运行状态、停用或删除任务、重置用户密码，但不能查看 Cookie 或密码明文。

系统必须与现有 BPS Docker 项目隔离，不复用其数据库、Redis、Celery、网络或反向代理配置。所有抖音任务全局串行执行，避免多个 Chromium 同时运行造成内存压力或重复发送。

## 2. 非目标

- 不提供公开注册、短信登录、邮箱验证或第三方 OAuth。
- 不支持用户之间共享抖音账号或任务。
- 不提供批量营销、群发、自动添加好友或绕过抖音风控的能力。
- 不允许管理员查看用户 Cookie、密码或其他凭据明文。
- 不在首版引入 MySQL、PostgreSQL、Redis、Celery、React 或独立 Node.js 前端构建链。
- 不修改或清理现有 BPS 容器、镜像、卷、网络和数据。

## 3. 用户与权限

### 3.1 角色

系统只有两个角色：

- `admin`：创建和停用用户、重置临时密码、查看全部任务与脱敏运行记录、停用/恢复/删除任务、查看系统健康状态。
- `user`：查看和修改自己的抖音账号、任务和运行记录；不能访问其他用户数据。

### 3.2 登录流程

1. 管理员创建用户名并生成一次性临时密码。
2. 用户首次登录后必须修改密码，完成前不能进入其他页面。
3. 密码使用 Argon2id 哈希保存；系统从不保存或回显密码明文。
4. 登录会话使用随机 256 位令牌。数据库只保存令牌哈希；浏览器 Cookie 设置 `HttpOnly`、`Secure`、`SameSite=Lax`，有效期 8 小时。
5. 所有状态修改请求必须通过 CSRF 校验。
6. 连续 5 次登录失败后锁定账号 15 分钟；管理员可提前解锁。

### 3.3 删除语义

- 删除任务：立即取消后续调度并硬删除任务配置；保留不含消息正文和凭据的审计事件 90 天。
- 删除抖音账号：先停用关联任务，再立即删除加密 Cookie；历史运行记录保留 90 天但仅保留账号显示名快照。
- 删除系统用户：先停用其全部任务并删除全部加密 Cookie，再停用用户记录。用户名和审计事件保留 90 天，便于追溯管理员操作。
- 所有删除操作都要求二次确认；账号和用户删除要求输入对象名称确认。

## 4. 数据模型

SQLite 数据库启用 WAL、外键约束和每日备份。所有时间戳以 UTC 保存，界面固定以 `Asia/Shanghai` 显示。

### 4.1 `users`

- `id`：UUID 主键
- `username`：唯一，3–32 个字符
- `password_hash`：Argon2id 哈希
- `role`：`admin` 或 `user`
- `status`：`active`、`locked`、`disabled`
- `must_change_password`：布尔值
- `failed_login_count`、`locked_until`
- `created_at`、`updated_at`

### 4.2 `douyin_accounts`

- `id`：UUID 主键
- `owner_user_id`：外键到 `users`
- `display_name`：用户自定义名称
- `encrypted_cookies`：AES-256-GCM 密文
- `cookie_nonce`：每行唯一随机 nonce
- `cookie_version`：便于密钥轮换
- `validation_state`：`unknown`、`valid`、`expired`、`invalid`
- `last_verified_at`、`created_at`、`updated_at`

Cookie 请求体上限为 128 KiB。保存后 API 只返回 `configured: true/false`、验证状态和最后验证时间，不返回密文或明文。

### 4.3 `spark_tasks`

- `id`：UUID 主键
- `owner_user_id`、`douyin_account_id`
- `target_name`：抖音搜索面板使用的精确昵称，1–64 个字符
- `send_time`：`HH:MM`，固定解释为 `Asia/Shanghai`
- `message_template`：1–500 个字符
- `enabled`：布尔值
- `next_run_at`：UTC 时间
- `created_at`、`updated_at`

一个账号可以有多条任务。相同账号、目标和发送时间的启用任务必须唯一，防止重复配置。

### 4.4 `task_runs`

- `id`：UUID 主键
- `task_id`、`scheduled_for`
- `status`：`queued`、`running`、`success`、`failed`、`skipped`
- `stage`：`queued`、`browser_start`、`login`、`target_search`、`compose`、`submit`、`finished`
- `started_at`、`finished_at`
- `error_code`、`error_summary`：脱敏后的可操作错误，不含 Cookie、Token、密码和页面私密内容
- `message_digest`：消息内容的 HMAC 摘要，只用于幂等诊断，不保存消息正文快照

数据库对 `(task_id, scheduled_for)` 建立唯一索引，避免同一次计划重复入队。

### 4.5 `audit_events`

记录登录、用户创建、密码重置、Cookie 更新、任务创建/修改/删除、任务启停和管理员操作。事件不记录密码、Cookie、Token、完整请求体或环境变量。

## 5. 调度与执行

### 5.1 调度器

- Worker 每 10 秒查询一次到期任务。
- 使用数据库租约和唯一索引抢占任务；任意时刻全局只允许一个 `running` 任务。
- 到期不超过 10 分钟的任务可以执行；超过 10 分钟则标记为 `skipped`，防止服务器恢复后集中补发。
- 失败任务不自动连续重试，避免重复消息。用户或管理员可在界面中手动重试一次，重试生成新的运行记录。
- 修改发送时间后立即重新计算 `next_run_at`；停用任务立即取消后续调度。

### 5.2 抖音发送流程

1. 解密当前账号 Cookie，仅保存在 Worker 进程内存中。
2. 启动独立无痕 Chromium context。
3. 打开抖音聊天页面并验证登录状态。
4. 优先使用搜索框和精确昵称定位目标；搜索失败时回退现有滚动会话列表逻辑。
5. 找不到目标时返回 `target_not_found`，任务为 `failed`，不能按成功退出。
6. 选中目标后输入消息并按 Enter 提交。
7. 确认输入框已清空，记录为 `success`；该确认表示页面已接受提交，不承诺对端即时送达。
8. 无论成功或失败都关闭 page、context 和 browser，清除内存中的 Cookie。

### 5.3 时间准确性门槛

服务器此前测得比客户端慢约 223 秒。正式启用新调度器前，必须只读确认时间同步来源，并使系统 UTC 偏差稳定小于 5 秒。任何时间服务修改都必须单独评估对 BPS 的影响并获得用户明确授权；不得通过给任务时间增加固定偏移来掩盖时钟错误。

## 6. 应用结构

首版采用一个 Python 代码库、一个共享 Docker 镜像、两个应用容器：

- `spark-web`：FastAPI、服务端 HTML、认证、RBAC、配置 API、管理员页面和健康检查。
- `spark-worker`：调度器、SQLite 租约、Playwright Chromium 和现有续火执行逻辑。

两个容器共享一个仅本 Compose 项目可访问的数据卷，存放 SQLite 与备份；共享只读主密钥挂载。Web 不启动 Chromium，Worker 不对外暴露端口。

### 6.1 资源限制

- `spark-web`：CPU 0.50，内存上限 256 MiB
- `spark-worker`：CPU 1.00，内存上限 768 MiB，任务并发数固定为 1
- 整个项目日志启用 Docker 日志轮转：单文件 10 MiB，最多 3 个文件
- 数据库每日保留 7 份备份

当前服务器清理后根分区约 8.1 GiB 可用、内存约 1.1 GiB 可用。部署前必须再次验证至少 5 GiB 磁盘可用；低于该门槛则停止构建和部署。

## 7. Docker 与网络隔离

- Compose 项目名固定为 `douyin-spark-console`。
- 使用独立 bridge 网络，不加入任何 `bps-*` 网络。
- 不挂载 Docker socket。
- 容器以非 root 用户运行；文件系统默认只读，仅数据卷和 `/tmp` 可写。
- `spark-web` 初始只绑定 `127.0.0.1:8899`，不得通过明文 HTTP 对公网开放。
- BPS 现有端口 `8888/8443`、容器、镜像、卷、网络和 Nginx 配置不得修改。
- 对朋友开放前，用户必须提供一个可解析到服务器的域名。经确认后使用独立 TLS 入口代理到 `127.0.0.1:8899`；TLS 配置不得复用或修改 BPS 的 Nginx 容器。
- 若公网防火墙或安全组需要改动，必须单独取得明确授权。

## 8. 密钥与凭据

- AES-256-GCM 主密钥和会话密钥分别生成，保存在宿主机 root 管理的 `0600` 文件中，以只读 secret 文件挂载到容器。
- 密钥不写入镜像、Compose 文件、Git、日志、数据库或环境变量输出。
- Cookie 解密只允许 Worker 执行；Web 仅能调用加密写入和状态查询接口。
- 备份中的 Cookie 保持加密；主密钥必须单独备份，且不与数据库备份放在同一目录。
- 管理员重置密码只生成新的临时密码，不读取旧密码。

## 9. 页面与视觉系统

产品主题为“火花守护”：面向非技术用户，页面的核心任务是让用户清楚知道下一次发送时间、当前状态以及失败后该怎么处理。

### 9.1 设计令牌

- 瓷白背景 `#F7F8FC`
- 墨蓝正文 `#182033`
- 珊瑚火花 `#FF6B57`
- 雾蓝分隔 `#E8ECF5`
- 青绿成功 `#1E9B72`
- 琥珀警告 `#D98E24`
- 字体：优先使用系统中文字体栈，标题采用 700 字重，正文采用 400/500 字重，数据与时间使用等宽数字特性
- 圆角控制在 10–14 px；阴影仅用于浮层和当前运行任务，不使用玻璃拟态或大面积渐变

### 9.2 标志性组件

每次执行以“火花轨迹”展示：等待 → 登录 → 找到好友 → 写入消息 → 已提交。当前步骤使用珊瑚火花点，成功步骤使用青绿，失败停在具体步骤并显示下一步操作。该轨迹只用于真实执行阶段，不作为装饰。

### 9.3 普通用户页面

- 登录与首次修改密码
- 首页：下一次发送、账号状态、最近一次结果、任务启停
- 抖音账号：添加/更新 Cookie、验证登录、删除账号
- 续火任务：目标昵称、每日时间、消息内容、启停
- 执行记录：状态、阶段、时间和脱敏错误说明

### 9.4 管理员页面

- 用户列表：状态、任务数、最近成功时间
- 全部任务：负责人、账号、目标、下次执行、状态
- 当前队列与最近失败
- 用户创建、临时密码重置、停用/恢复
- 任务停用、恢复、删除与审计记录

桌面端使用窄侧栏和主内容区；移动端使用底部导航。任务编辑采用单页分区表单，不使用冗长向导。所有键盘焦点可见，颜色不是唯一状态信号，并尊重 `prefers-reduced-motion`。

## 10. API 与错误契约

API 使用 `/api/v1` 前缀。所有写操作返回统一结构：

```json
{
  "ok": false,
  "error": {
    "code": "target_not_found",
    "message": "未找到目标好友，请确认昵称后重试。"
  }
}
```

错误码至少包括：`invalid_credentials`、`password_change_required`、`forbidden`、`cookie_invalid`、`cookie_expired`、`target_not_found`、`browser_start_failed`、`message_submit_failed`、`task_already_running`、`system_time_unhealthy`。

普通用户访问不属于自己的资源统一返回 404，避免泄露资源存在性。管理员危险操作需要再次验证当前密码或使用 10 分钟内的提升授权会话。

## 11. 测试与验收

### 11.1 自动化测试

- 用户隔离与管理员 RBAC
- 临时密码和首次修改流程
- 密码锁定与会话过期
- Cookie 加密往返、错误密钥、密文篡改
- 任务时间计算、时区、错过任务和禁用任务
- 数据库租约、并发抢占和 `(task_id, scheduled_for)` 幂等
- 搜索面板精确匹配、滚动回退和目标未找到失败
- 删除任务、账号和用户的级联与审计语义
- API CSRF、越权访问和敏感字段不回显

### 11.2 部署验收

1. 构建镜像前验证 BPS 五个容器 ID、健康状态和 HTTP 响应。
2. 新 Compose 启动后再次验证 BPS 状态完全不变。
3. 验证 Web/Worker 健康检查、资源限制、日志轮转和数据库备份。
4. 使用测试用户完成登录、改密、账号保存、Cookie 验证和任务 CRUD。
5. 使用真实账号执行“只搜索并选中，不输入、不发送”的安全探测。
6. 只有在用户明确同意后执行一次受控真实发送。
7. 验证失败任务返回非零业务结果，并在页面显示明确阶段。

## 12. 现有任务迁移

1. 新系统以 Worker 禁用状态部署。
2. 备份 `/opt/douyin-spark-flow`、两份 systemd unit 和现有加密前的本地配置文件权限/哈希；备份不得输出 Cookie。
3. 将 WZ、GSY 两个账号和任务导入新数据库，Cookie 在写入时立即加密。
4. 对两个账号分别运行“登录 + 搜索目标”的无发送验证。
5. 在明确维护窗口内停止并禁用旧两个 timer，再启用新 Worker；不得删除旧 unit 和配置。
6. 首次真实定时执行后核对双方收件情况和运行记录。
7. 若新系统失败，停止新 Worker并重新启用旧 timer；数据库与容器保留用于诊断。

## 13. 回滚与恢复

- Docker 回滚：停止 `douyin-spark-console` Compose，不删除数据卷；重新启动旧 systemd timer。
- 数据恢复：从最近一份 SQLite 备份恢复，恢复前先保存故障数据库副本。
- 镜像回滚：保留最近一个已验证镜像标签，确认新版本稳定后才允许回收旧标签。
- BPS 验证：任何部署、回滚或镜像清理后都重新核对原 5 个容器 ID、MySQL health 和 HTTP 状态。

## 14. 上线门槛

以下条件必须全部满足才能对朋友开放：

- 用户确认本规格与实施计划。
- 服务器时间偏差稳定小于 5 秒。
- 根分区可用空间不少于 5 GiB。
- 提供可解析到服务器的独立域名，并完成可信 HTTPS。
- 管理员账号已创建，默认或临时凭据已更换。
- Cookie 加密密钥已完成独立备份。
- BPS 五个容器在部署前后状态一致。
- 自动化测试全部通过，且完成一次无发送真实页面探测。
