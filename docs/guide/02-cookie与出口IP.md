# Cookie 与出口 IP

理解这一节，是稳定使用本项目的前提。

## 核心结论

抖音会校验登录 Cookie 的**出口 IP**。也就是说：

> 抓取 Cookie 时浏览器用的出口 IP，必须和定时任务运行时用的出口 IP **一致**，否则登录态会掉。

如果不一致，就会出现「明明抓到了 Cookie、任务却登录失败 / 登录态掉」的情况。

## 三种部署方式怎么保证一致

| 方式 | 抓 Cookie 的出口 | 跑任务的出口 | 是否一致 |
| --- | --- | --- | --- |
| 服务器 Docker | 借服务器上的 gost 隧道 | 服务器本身 | ✅ 天然一致 |
| 云函数 | 借 gost 函数（同地域） | 云函数 | ✅ 同地域一致 |
| GitHub Action | 需要自配固定代理 | runner 出口（漂移） | ❌ 需额外处理 |

## configTool 的配套代理

本地配置生成器（configTool）抓 Cookie 时，可以走一条「配套代理」隧道，让抓取动作的出口和任务运行时的出口落在同一处。

隧道链路（以 Docker 为例）：

```
浏览器 → 本地 gost（HTTP 代理）→ ws 隧道 → 服务器上的 gost 容器 → 目标站
```

这样你在本机抓 Cookie，出口 IP 却是服务器的 IP，和之后服务器跑任务的 IP 一致。

## GitHub Action 的特殊情况

Action 每次运行出口 IP 都变，所以：

1. 需要自备一个固定出口的 HTTP 代理；
2. 把代理地址写进 `.env` 的 `PROXY_ADDRESS`；
3. 抓 Cookie 时也要走同一个代理出口。

否则登录态会随 IP 漂移而失效。这也是 GitHub Action 被视为「过时」方案的主要原因之一。
